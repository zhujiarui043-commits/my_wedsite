# Jerry Zhu · Personal Homepage

A local Next.js personal website. The homepage opens with a full-screen photograph, gradually blurs and darkens the background, and brings the profile content up from the bottom. The content sits directly over the photograph with no opaque panel. The left third contains the profile; the right two thirds show a large handwritten welcome, with a lyric ticker in the bottom-right corner. All website interface text is in English; supplied lyrics appear in their original language.

## Run locally on Windows

Node.js 22.13 or later is required. In PowerShell:

```powershell
cd C:\Users\jiaru\Desktop\site\jerry-journal-local\jerry-journal-local
npm.cmd install
npm.cmd run dev
```

Open http://127.0.0.1:3000. Keep the terminal running; press Ctrl+C to stop.

Once dependencies are installed, only `npm.cmd run dev` is needed. Using `npm.cmd` also works when PowerShell blocks `npm.ps1`.

## Customize the homepage

- Profile text, interests, location, music, MBTI, and zodiac sign: `lib/profile.ts`. Location appears directly below the cycling/interests line.
- Background photograph: `public/background.jpg`.
- Background blur strength: `--home-background-blur` in `app/home.css` (currently 6 px).
- White Fudan University emblem: `public/icons/fudan.svg`, displayed before the university name.
- Circular portrait: add `public/profile.jpg`, then set `photo: '/profile.jpg'` in `lib/profile.ts`.
- Personality line: set `mbti` and `zodiac`; leave both empty to hide that line.
- Homepage layout: `app/page.tsx`.
- Homepage styling and animation timing: `app/home.css`.
- Image loading and entrance sequence: `components/home-intro.tsx`.
- Welcome message: `components/home-welcome.tsx` and `lib/welcome.ts`. The visitor's local entry time selects morning (05:00–11:59), afternoon (12:00–17:59), or night (18:00–04:59). SVG pen strokes write the greeting, "Welcome to", and "My Space!" once during the entrance, taking about 7 seconds. Reduced-motion preferences show the finished writing immediately. On mobile the welcome appears below the profile. Vector glyph data and attribution are in `lib/handwriting/`.
- Homepage navigation: the links below the welcome open `/about`, `/journey`, `/gallery`, `/music`, and `/notes`. Labels and descriptions are in `lib/spaces.ts`. Pages share the background, navigation, and entrance animations. Pages are in `app/(spaces)/`, with their shared scaffold in `components/space-page.tsx` and styling in `app/(spaces)/spaces.css`.
- Journey map: `components/journey-map.tsx` and `components/journey-map-markers.tsx`. The enlarged map covers China's land area through Korea and Japan, excluding Southeast Asia and the Indian peninsula. Red dots mark the cities in `lib/journey-places.ts`; city names appear on hover, keyboard focus, or tap. Hovering closely spaced dots lists nearby visited cities together. Each city's `country` uses a Natural Earth country code (CHN, JPN, or KOR); visited countries automatically receive the brighter outline. Empty map areas have no hover tooltip. Map outlines in `lib/maps/east-asia.json` are generated by `scripts/generate-journey-map.cjs` from [Natural Earth](https://www.naturalearthdata.com/) (public domain); coordinates use the [GeoNames gazetteer](https://www.geonames.org/export/) (CC BY).
- Journey journals: the place links on the lower left of `/journey` open `/journey/[place]`. `lib/journey-destinations.json` supplies the initial nine places in their existing order. Jerry Studio can add, edit, or delete destination pages, their text, and an optional photo; changes are stored in `data/destinations.json`. Enter a longitude and latitude together to add or update a red dot within the current map. Country outlines follow the selected country. The initial city dots remain when deleting a destination journal. Updates appear on refresh without rebuilding. Empty journals display "More coming soon."
- Notes: `/notes` lists published essays by date, with an optional photo and excerpt. `/notes/[id]` displays the complete text, preserving paragraph breaks and newlines. No example essays are shown when the collection is empty.
- Gallery: `/gallery` centers the title above a three-dimensional sphere of selected highlights, with small empty caps at both poles. The existing collection stays selected when upgrading; new Studio uploads wait for a selection. Drag to rotate, release for decaying inertia, click for a small nudge, and double-click a photo to view its larger version. Perspective-aware checks keep a gap between visible photographs; a crowded edge photograph can temporarily leave view, and becomes visible when rotated to the front. The sphere supports touch dragging, arrow keys, a reset button, and reduced-motion preferences. Text enters from below while photos resolve from blur without moving the sphere. Rotation pauses when the page is hidden, the sphere is offscreen, or a photo is open.
- Supplied Gallery collection: originals are in `photos/` (ignored by Git). `npm.cmd run gallery:prepare` generates uncropped, correctly oriented WebP thumbnails and larger versions in `public/gallery/`, and metadata in `lib/gallery-photos.json`. Original files are preserved; existing assets and metadata are reused, and duplicate photographs are skipped. The prepared assets are included in source deployments and desktop builds. The initial collection is also available in Jerry Studio when no saved content database exists; subsequent edits and deletions are saved in `data/posts.json`. The displayed dates are left blank until provided by the author.
- Gallery likes: every photograph has a small heart and count in its lower-right corner, with a larger control on the opened photograph. Click to like; click again to undo. An anonymous browser cookie remembers the visitor's choice, and duplicate requests do not add extra votes. Counts are shared by visitors, saved on the website server, refreshed periodically, and synchronized across tabs. Both seeded photographs and Studio uploads support likes. No login is required.
- Gallery albums: collections appear below the photo planet, each with its name, manually selected cover, and photograph count. Clicking a collection opens `/gallery/albums/[id]`, with a photo grid, full-size viewing, and the same per-photo likes used on the planet. No sample albums are created automatically.
- Music: `/music` displays the May–October 2026 listening reports on the right. Choose a month to see its song count, report comparison, lyric keyword, most-played song, and top ten tracks. Late-night listening, a dated repeat, first artist encounters, and new favorites appear only when supplied by the report. A repeat records its actual song independently of the monthly number-one track. The ranking has its own visible scrollbar and supports keyboard scrolling. Switching months resets the ranking to the top. Continuous-listening streaks and artist-companion counts are omitted. `lib/music-reports.json` stores the supplied report figures and ranking order; song titles retain their original language, including Chinese and Japanese, while interface labels remain in English. Percentage changes follow the screenshots; September is an increase from August. May has no earlier-month comparison, and August has no supplied late-night record. The August 28 repeat is Transformers Prime by Brian Tyler, with two plays; its full title was confirmed by the user. The trend uses only the supplied months, without estimating earlier counts. Append later reports to this file to extend the archive. Record icons represent tracks and do not claim to reproduce album artwork.
- GitHub, Gmail, Douyin, and rednote contact details, displayed in that order: `contacts` in `lib/profile.ts`. GitHub currently shows the supplied display name; leave an account empty to display "Not added yet". The contact heading, icons, and popup text use gray.
- Social icons and account popups: `components/social-logos.tsx` and `public/icons/`. Hover or focus an icon to preview its account; click or tap to keep it open. Click the icon again, click outside, or press Escape to close. External links are not connected yet.
- Site title, description, and language: `app/layout.tsx`.
- Lyric collection: `lyric.txt` in the project root, one lyric per line, currently in Traditional Chinese. Blank lines are ignored. Edit this file and refresh during development; rebuild to update a production site.
- Lyric ticker: `components/lyrics-ticker.tsx` and `app/home.css`. Each page load shuffles the lyrics after hydration, then continuously scrolls them from right to left after the entrance finishes. The end joins seamlessly back to the beginning. The top and bottom edges have white lines that fade toward both ends. Hover or keyboard focus pauses scrolling. Reduced-motion preferences show one static lyric. On mobile the ticker sits below the welcome to avoid overlapping content.

The background starts blurring and darkening after 300 ms over 2.4 seconds. Content begins rising after 900 ms over 2.2 seconds and settles after a small bounce. The full entrance takes about 3.1 seconds after the photograph loads. Animation timing is controlled by the variables at the top of `app/home.css`. Reduced-motion preferences display the profile immediately against the darkened, blurred photograph.

## Jerry Studio · Windows application

Jerry Studio is the private desktop content editor for this website. It has three sections:

- **Notes:** publish, edit, and delete essays, with one optional photograph per entry.
- **Gallery → Photo planet:** upload, edit, and delete photographs with a title, date, location, and optional caption. **Show on photo planet** selects highlights independently of album membership; list checkboxes save immediately, while the editor checkbox is saved with the photograph. Removing a highlight preserves its photographs and likes in every album. Refresh Gallery to see the updated selection.
- **Gallery → Albums:** name a collection, select existing photographs, and choose one of them as the cover. **Upload photos** accepts multiple JPG, PNG, or WebP files (up to 12 MB each) and saves them to the photo library; save the album to keep its membership and cover. Use **Show selected only** to review or remove album photographs. Click a photograph's star to immediately add or remove a planet highlight. A photograph may belong to multiple albums; every view uses the same photo ID and likes. Removing it from an album or deleting an album preserves the original photograph, its planet selection, and its likes. Deleting a photograph in **Photo planet** removes it from all albums; if it was a cover, choose a replacement cover before saving that album again. Album changes survive restarting Studio.
- **Journey:** manage destination pages, travel text, an optional photograph, and optional map coordinates. Existing place URLs remain stable when edited; new page addresses use lowercase English letters, numbers, and hyphens.

Create the standalone Windows build:

```powershell
npm.cmd run desktop:build
```

Open `Jerry Studio.exe` inside the newest `dist-desktop/JerryStudio-0.1.0-win-x64-*` folder. Keep the complete folder together; the application includes its own runtime and automatically starts its local website. A terminal or a separate Node installation is not needed to use the packaged app. Its server stops when the app closes. `dist-desktop/latest.json` records the latest executable path.

Run `npm.cmd run desktop:shortcut` after building to create or update the **Jerry Studio** desktop shortcut.

The packaged build points to this project's existing `data` folder through `resources/content-directory.json`; both the app and the local development website therefore use the same content. Do not delete that folder when updating the application. If relocating the project, update the absolute `path` in this configuration file. `JERRY_DATA_DIR` can select another content folder for the website or when building the app.

Use **View website** to preview the bundled website. Use **File → Open content folder** to locate your content, and **File → Back up content…** to copy it to another folder. Back up before deleting important entries. Close other editing windows while creating a backup.

The desktop shell uses [Electron](https://www.electronjs.org/docs/latest/); the editor, storage, and desktop main process can be reused for a future Mac build. This repository currently packages Windows only; a Mac release still needs packaging and testing on macOS.

The same editor is available locally at http://127.0.0.1:3000/studio. The desktop app and this page publish to the local website and any running temporary preview that uses the same content folder. Publishing to a permanently hosted website requires that hosting service to use a shared content store or an upload connection; it is not configured by this local app.

## Content storage

- Photo journal: http://127.0.0.1:3000/moments.
- Content editor: http://127.0.0.1:3000/studio, also used inside Jerry Studio.
- Sample content: `lib/demo.ts` is only used by the older `/moments` journal.
- Text and metadata are saved in `data/posts.json`.
- Destination pages are saved in `data/destinations.json`.
- Album names, chosen covers, and photograph memberships are saved in `data/albums.json`. Albums reference the existing photographs rather than making extra copies. Planet selections are saved as `featured` on the same photographs in `data/posts.json`; older photographs without this field remain featured.
- Gallery counts and hashed visitor IDs are saved in `data/gallery-likes.json`; include this file in content backups. Sharing the same content folder shares counts across the local site, Studio preview, and temporary public preview. Separately hosted copies need their own persistent content storage.
- Uploaded images are saved in `data/images/`. JPEG, PNG, and WebP are supported, up to 12 MB per image.
- Back up the entire `data` folder. Deleting an entry also permanently deletes its associated photograph.
- `data` is ignored by Git, so syncing source code to GitHub does not back up published text or uploaded images.

The development server listens only on this computer and stores data locally. Temporary sharing uses a separate production preview; permanent hosting needs its own deployment setup.

## Share a temporary preview

Run `npm.cmd run share` from the project folder. It builds the current website, starts a production server on `127.0.0.1:3100`, and shares the public relay on `127.0.0.1:3101` through a Cloudflare Quick Tunnel. Copy the printed `https://....trycloudflare.com` address to your friends. Keep the computer awake, online, and the sharing process running; Ctrl+C stops sharing. Each new tunnel gets a new address.

The relay shares only the homepage, About, Journey (including currently published destination journals), Gallery (including individual albums), Music, Notes (including individual essays), static assets, and uploaded images referenced by published content. New entries become available without restarting the relay. The Gallery likes endpoint accepts only small, same-origin votes for published photographs and forwards only the anonymous visitor cookie. Unattached uploaded images, `/studio`, `/api/posts`, `/api/albums`, `/api/gallery/featured`, and `/api/destinations` remain private. All content upload/edit/delete requests are blocked. Local development and editing on port 3000 continue as before.

The Windows tunnel executable is stored at `node_modules/.cache/jerry-preview/cloudflared.exe`, outside committed source. If it is removed, download the Windows amd64 executable from the [official Cloudflare releases](https://github.com/cloudflare/cloudflared/releases), then restore that path or set `CLOUDFLARED_PATH` to the executable. No Cloudflare account or domain is required for this temporary URL. See [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) for service limitations.
