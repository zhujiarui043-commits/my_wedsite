# Jerry Zhu · Personal Homepage

A local Next.js personal website. The homepage opens with a full-screen photograph, gradually blurs and darkens the background, and brings the profile content up from the bottom. The content sits directly over the photograph with no opaque panel. The left third contains the profile; the right two thirds show a large handwritten welcome, with a lyric ticker in the bottom-right corner. All website interface text is in English; supplied lyrics appear in their original language.

## Run locally on Windows

Node.js 22.13 or later is required. In PowerShell:

```powershell
cd C:\Users\jiaru\Desktop\site\jerry-journal-local\jerry-journal-local
npm.cmd install
npm.cmd run dev
```

Open http://127.0.0.1:3000. Keep the terminal running; press Ctrl+C to stop.

Once dependencies are installed, only `npm.cmd run dev` is needed. Using `npm.cmd` also works when PowerShell blocks `npm.ps1`.

## Customize the homepage

- Profile text, interests, location, music, MBTI, and zodiac sign: `lib/profile.ts`. Location appears directly below the cycling/interests line.
- Background photograph: `public/background.jpg`.
- Background blur strength: `--home-background-blur` in `app/home.css` (currently 6 px).
- White Fudan University emblem: `public/icons/fudan.svg`, displayed before the university name.
- Circular portrait: add `public/profile.jpg`, then set `photo: '/profile.jpg'` in `lib/profile.ts`.
- Personality line: set `mbti` and `zodiac`; leave both empty to hide that line.
- Homepage layout: `app/page.tsx`.
- Homepage styling and animation timing: `app/home.css`.
- Image loading and entrance sequence: `components/home-intro.tsx`.
- Welcome message: `components/home-welcome.tsx` and `lib/welcome.ts`. The visitor's local entry time selects morning (05:00–11:59), afternoon (12:00–17:59), or night (18:00–04:59). SVG pen strokes write the greeting, "Welcome to", and "My Space!" once during the entrance, taking about 7 seconds. Reduced-motion preferences show the finished writing immediately. On mobile the welcome appears below the profile. Vector glyph data and attribution are in `lib/handwriting/`.
- Homepage navigation: the links below the welcome open `/about`, `/gallery`, `/journey`, `/music`, and `/notes`, in that order. Labels and descriptions are in `lib/spaces.ts`. Pages share the background, navigation, and entrance animations. Pages are in `app/(spaces)/`, with their shared scaffold in `components/space-page.tsx` and styling in `app/(spaces)/spaces.css`.
- Journey map: `components/journey-map.tsx` and `components/journey-map-markers.tsx`. The enlarged map covers China's land area through Korea and Japan, excluding Southeast Asia and the Indian peninsula. Red dots mark the cities in `lib/journey-places.ts`; city names appear on hover, keyboard focus, or tap. Hovering closely spaced dots lists nearby visited cities together. Each city's `country` uses a Natural Earth country code (CHN, JPN, or KOR); visited countries automatically receive the brighter outline. Empty map areas have no hover tooltip. Map outlines in `lib/maps/east-asia.json` are generated by `scripts/generate-journey-map.cjs` from [Natural Earth](https://www.naturalearthdata.com/) (public domain); coordinates use the [GeoNames gazetteer](https://www.geonames.org/export/) (CC BY).
- Journey journals: the place links open `/journey/[place]`. `lib/journey-destinations.json` supplies the initial nine places; `data/destinations.json` supplies saved destination pages, text, optional photographs, and coordinates. Updates appear on refresh without rebuilding. Empty journals display "More coming soon."
- Guestbook: `/notes` is the public nickname-based message board. Visitors can leave messages, reply in threads, and like messages or replies without registering. Messages are plain text; an anonymous browser cookie remembers likes, and repeat requests do not add duplicate votes or messages. The page and navigation use the English name Guestbook. Messages refresh periodically, and longer collections have a More messages control. Existing essay data and `/notes/[id]` links remain available at their existing public addresses.
- Gallery: `/gallery` centers the title above a three-dimensional sphere of selected highlights, with small empty caps at both poles. The existing collection stays selected when upgrading; imported album photographs stay outside the sphere unless selected. Drag to rotate, release for decaying inertia, click for a small nudge, and double-click a photo to view its larger version. Perspective-aware checks keep a gap between visible photographs; a crowded edge photograph can temporarily leave view, and becomes visible when rotated to the front. The sphere supports touch dragging, arrow keys, a reset button, and reduced-motion preferences. Text enters from below while photos resolve from blur without moving the sphere. Rotation pauses when the page is hidden, the sphere is offscreen, or a photo is open.
- Supplied Gallery collection: originals are in `photos/` (ignored by Git). `npm.cmd run gallery:prepare` generates uncropped, correctly oriented WebP thumbnails and larger versions in `public/gallery/`, and metadata in `lib/gallery-photos.json`. Original files are preserved; existing assets and metadata are reused, and duplicate photographs are skipped. The prepared assets are included in source deployments. The initial collection is loaded when no saved content database exists; imported photograph metadata is saved in `data/posts.json`. The displayed dates are left blank until provided by the author.
- Gallery likes: every photograph has a small heart and count in its lower-right corner, with a larger control on the opened photograph. Click to like; click again to undo. An anonymous browser cookie remembers the visitor's choice, and duplicate requests do not add extra votes. Counts are shared by visitors, saved on the website server, refreshed periodically, and synchronized across tabs. Both seeded and imported photographs support likes. No login is required.
- Gallery albums: collections appear below the photo planet, each with its name, manually selected cover, and photograph count. Clicking a collection opens `/gallery/albums/[id]`, with a photo grid, full-size viewing, and the same per-photo likes used on the planet. No sample albums are created automatically. An optional `coverPosition` sets the visible part of a cover without cropping its original photograph; resaving the same cover preserves its position.
- Music: `/music` uses a centered title like Gallery, with the May–October 2026 listening reports in a centered column below it. Choose a month to see its song count, report comparison, lyric keyword, most-played song, and top ten tracks. Late-night listening, a dated repeat, first artist encounters, and new favorites appear only when supplied by the report. A repeat records its actual song independently of the monthly number-one track. The ranking has its own visible scrollbar and supports keyboard scrolling. Switching months resets the ranking to the top. Continuous-listening streaks and artist-companion counts are omitted. `lib/music-reports.json` stores the supplied report figures and ranking order; song titles retain their original language, including Chinese and Japanese, while interface labels remain in English. Percentage changes follow the screenshots; September is an increase from August. May has no earlier-month comparison, and August has no supplied late-night record. The August 28 repeat is Transformers Prime by Brian Tyler, with two plays; its full title was confirmed by the user. The trend uses only the supplied months, without estimating earlier counts. Append later reports to this file to extend the archive. Record icons represent tracks and do not claim to reproduce album artwork.
- Music recordings: **Piano Recordings** and **Concert Recordings** appear below the listening ranking, initially collapsed. Click, tap, or use the keyboard to expand each section independently. `lib/music-recordings.ts` stores each group's video titles, source URLs, and optional posters. The first piano recording is 伤信, with its supplied cover; the concert collection is awaiting videos. Playback assets are in `public/music-recordings/`. The website uses a 1080p H.264/AAC MP4 with fast start for browser playback. Videos use native controls, support inline playback on phones, load on demand, and pause when their section is closed. Switching report months preserves the recording sections' open state.
- GitHub, Gmail, Douyin, and rednote contact details, displayed in that order: `contacts` in `lib/profile.ts`. GitHub currently shows the supplied display name; leave an account empty to display "Not added yet". The contact heading, icons, and popup text use gray.
- Social icons and account popups: `components/social-logos.tsx` and `public/icons/`. Hover or focus an icon to preview its account; click or tap to keep it open. Click the icon again, click outside, or press Escape to close. External links are not connected yet.
- Site title, description, and language: `app/layout.tsx`.
- Lyric collection: `lyric.txt` in the project root, one lyric per line, currently in Traditional Chinese. Blank lines are ignored. Edit this file and refresh during development; rebuild to update a production site.
- Lyric ticker: `components/lyrics-ticker.tsx` and `app/home.css`. Each page load shuffles the lyrics after hydration, then continuously scrolls them from right to left after the entrance finishes. The end joins seamlessly back to the beginning. The top and bottom edges have white lines that fade toward both ends. Hover or keyboard focus pauses scrolling. Reduced-motion preferences show one static lyric. On mobile the ticker sits below the welcome to avoid overlapping content.

The background starts blurring and darkening after 300 ms over 2.4 seconds. Content begins rising after 900 ms over 2.2 seconds and settles after a small bounce. The full entrance takes about 3.1 seconds after the photograph loads. Animation timing is controlled by the variables at the top of `app/home.css`. Reduced-motion preferences display the profile immediately against the darkened, blurred photograph.

## Content storage

Image grids and album covers load cached 320px/960px WebP previews; opening a photograph loads its original. Originals, album membership, cover framing, and likes are preserved. Preview files live in `data/image-previews/` and can be regenerated with `npm.cmd run gallery:previews`; builds prepare them automatically. New images also generate their previews on first use, with at most two conversions running at once. Keep the entire `data` folder when moving the website.

The preparation command also updates lightweight display versions when the original avatar, About portrait, or piano cover changes. The planet batches drag drawing into animation frames and stops when hidden or idle. The lyric ticker renders only the previous, current, and next line. Recording players mount when their section opens, release when it closes, and pause other players when playback starts.

- Photo journal: http://127.0.0.1:3000/moments.
- Sample content: `lib/demo.ts` is only used by the older `/moments` journal.
- Text and metadata are saved in `data/posts.json`.
- Destination pages are saved in `data/destinations.json`.
- Guestbook messages and hashed anonymous likes are saved in `data/guestbook.json`. Include it in content backups.
- Album names, chosen covers, and photograph memberships are saved in `data/albums.json`. Albums reference the existing photographs rather than making extra copies. Planet selections are saved as `featured` on the same photographs in `data/posts.json`; older photographs without this field remain featured.
- Gallery counts and hashed visitor IDs are saved in `data/gallery-likes.json`; include this file in content backups. Sharing the same content folder shares counts across the local site and temporary public preview. Separately hosted copies need their own persistent content storage.
- Uploaded images are saved in `data/images/`. JPEG, PNG, and WebP are supported, up to 12 MB per image.
- Back up the entire `data` folder before changing content files.
- `data` is ignored by Git, so syncing source code to GitHub does not back up published text or uploaded images.

The development server listens only on this computer and stores data locally. Temporary sharing uses a separate production preview; permanent hosting needs its own deployment setup.

## Share a temporary preview

Run `npm.cmd run share` from the project folder. It builds the current website, starts a production server on `127.0.0.1:3100`, and shares the public relay on `127.0.0.1:3101` through a Cloudflare Quick Tunnel. Copy the printed `https://....trycloudflare.com` address to your friends. Keep the computer awake, online, and the sharing process running; Ctrl+C stops sharing. Each new tunnel gets a new address.

The relay shares only the homepage, About, Journey (including currently published destination journals), Gallery (including individual albums), Music, Guestbook, and existing individual essay pages, static assets, and uploaded images referenced by published content. New entries become available without restarting the relay. The Gallery likes endpoint accepts only small, same-origin votes for published photographs and forwards only the anonymous visitor cookie. Unattached images and unrecognized routes are blocked. The former desktop editor, `/studio`, and its editing/upload endpoints have been removed. The Guestbook endpoint also accepts validated, same-origin messages, replies, and likes, forwarding only its anonymous visitor cookie. Other content upload/edit/delete requests are blocked. Local development on port 3000 continues as before.

The Windows tunnel executable is stored at `node_modules/.cache/jerry-preview/cloudflared.exe`, outside committed source. If it is removed, download the Windows amd64 executable from the [official Cloudflare releases](https://github.com/cloudflare/cloudflared/releases), then restore that path or set `CLOUDFLARED_PATH` to the executable. No Cloudflare account or domain is required for this temporary URL. See [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) for service limitations.
